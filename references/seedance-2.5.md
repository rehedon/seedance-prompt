## Capability And Mode Routing

先按实际任务选择模式，不要把“2.5”本身当作模式：

| 用户目标 | 模式/界面选择 | 时长与关键规则 |
|---|---|---|
| 文生视频、全能参考、首尾帧 | 普通生成对应模式 | `duration` 4–30 秒（97–721 帧）；选择能完成内容的最短稳定时长 |
| 一次生成完整长场景 | 超长视频 | 30–180 秒；必须有宏观段落和稀疏时间轴，不把无关镜头拼成长视频 |
| 继续已有视频 | 视频延长 | 原视频需在 30 秒以内；单次最高延长约 30 秒，可多次延长，总片段最长约 60 秒 |
| 修改已有视频局部内容 | 智能编辑/高级编辑/视频编辑 | 明确“保持不变”与“只修改”；视频输入 20 秒以内通常更稳定 |
| 改机位或视角 | 智能编辑/高级编辑 | 锁定人物、动作、场景身份，写新方位、高度、角度、景别和需要补全的空间 |
| 删除 BGM | 智能编辑 | 移除音乐，保留人声、必要原声、画面和已有字幕，除非用户另有要求 |
| 白模/轨迹控制 | 白模控制 | 白模只控制机位、站位、运动轨迹和动作时机，不替代最终人物与材质设定 |
| 绿幕、局部消除、两视频过渡、多宫格 | 对应编辑/参考入口 | 精确写保留项、修改项、参考格映射或两端连续关系 |

当前界面显示的模式名称和可用参数优先。普通模式下用户要求 31 秒以上，不能直接把 `duration` 写成 31–180 秒；应选择“超长视频”或拆为多个普通生成任务。

## Official Prompt Formula

官方基础结构为：

`素材描述 + 一句话概述 + 具体情节描述 + 全局补充（结尾）`

- 素材描述：按上传顺序写素材编号和具体用途；无素材时省略。
- 一句话概述：主体 + 地点 + 事件 + 题材/风格 + 特殊运镜。
- 具体情节：按故事线或时间轴写；每段包含画面、运镜、动作、台词、音效以及必要的反向描述。
- 全局补充：重申贯穿全片的机位、环境、氛围、光影、声音和全局禁止项。

输出时把结构写成一段连贯、可直接使用的提示词；用户需要审阅结构时才保留小标题。

## Time Control

普通细腻表演或单一连续动作使用自然阶段：开场、发展、峰值、余波、尾帧。

以下情况使用时间戳：动作必须在指定秒数发生、台词/动作同步、接触或爆炸、转场、身份揭示等不可逆事件。时间点优先用整数秒或清楚区间，每个锚点只安排一个主要事件，不为呼吸、头发、衣物、雨雾、烟尘和背景人群逐秒编舞。

实用密度上限：

- 4–15 秒：通常不超过 4 个必要锚点。
- 16–30 秒：通常不超过 7 个必要锚点。
- 30–180 秒超长：先分宏观段落，每个短节拍通常只设一个核心锚点。

这是一条稳定性约束，不是要求用满锚点。

## 30-second And Ultra-long Structure

16–30 秒、连续表演或一镜到底优先采用：

1. 总述：一句话描述全片基调和唯一序列目标。
2. 多模态参考层：每个真实素材控制什么、必须保持什么。
3. 全局设定：时间地点、物理质感、视觉风格、景深/打光、镜头语言、主体造型、表演核心和禁止项。
4. 时间轴：每段写画面、动作、表演、摄影、台词/声音和状态变化；相邻段必须因果连续。
5. 全局补充：重申身份一致、场景连续和无字幕/无水印/无无关 BGM。

30–180 秒超长模式必须先建立宏观段落，再细分短节拍；整个任务仍只有一个宏观场景目标。若包含换场、跳时、平行叙事或多个互不相关目标，优先拆成多个任务。

## Multimodal References

- 使用 `@图片N`、`@视频N`、`@音频N`，编号必须匹配上传顺序。
- 人物身份、场景、构图/白模、动作/运镜、音色分开指定，避免同一素材承担互相冲突的职责。
- 官方建议视频编辑输入控制在 20 秒以内效果较好；视频参考图编辑通常 1–5 张更稳，6–8 张可尝试但稳定性下降。
- 超过 5 个主体时，单视图通常更稳定；需要多视角时优先拆成多张不同视图，而不是一张图塞入多个视角。
- 多人同框时逐人绑定参考和独立外观特征，写明谁在画面哪一侧、做什么、看向谁。

## Task-specific Prompt Contracts

### Extend

写清承接的最后一刻：人物姿态、位置、速度、方向、支撑、光线、声音余韵。只描述新增动作和状态变化，不复述原视频已完成内容。除非故事收束，尾帧继续保留可延长的动态。

### Edit / Camera Edit

先写“保持不变”：人物身份、服装、时长、台词、场景、未选区域等。再写“只修改”：对象、区域、时间范围和目标结果。最后写修改引发的自然光影、遮挡、接触和声音反馈。

### First/Last Frame And Transition

锁定首帧初态与尾帧目标态，描述中间变化的动力与因果，不让物体无理由溶解或瞬移。连接两个视频时只补全两端间隙，分别继承前视频尾帧和后视频首帧的人物、运动方向、光线与声音。

### White Model / Multi-panel

白模只提供机位、站位、路线、动作时机和空间比例；另写最终人物、材质、灯光与美术。多宫格逐格对应时间段，并补齐每格景别、角度、构图、运镜、动作和衔接。

## 2.5 Delivery Skeleton

骨架只用于组织，最终删除未使用项和全部花括号占位符：

```text
基于@图片1严格保持人物面容、发型和服装一致；@视频1只参考动作节奏和镜头运动；@音频1只参考音色与语速。

[主体]在[地点]完成[唯一核心事件]，[题材/视觉风格]，[关键摄影意图]。

0s–Xs：[开场状态、画面、动作、表演、景别/角度/机位/运镜、环境声]。
Xs–Ys：[发展与因果、摄影变化、台词/拟音、状态增量]。
Ys–结束：[峰值、余波与可用尾帧]。

全片保持[身份、场景、物理、光影和声音连续项]。无字幕、无水印、无多余文字、无无关BGM；避免[当前任务的具体失败项]。
```

## Check

- 普通生成 4–30 秒；超长模式 30–180 秒；延长与编辑遵守各自入口条件。
- 提示词含官方四层结构所需信息，但没有无效模板标签。
- 时间轴稀疏且因果连续，没有多个竞争主事件挤在同一时刻。
- 编辑类提示词同时写清保持不变与只修改。
- 参考素材编号、职责和用户实际输入一致。
